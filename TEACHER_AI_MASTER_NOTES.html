Chapter 1

The Foundations (Zero to Hero)

Bhai, interview me fail hone ka sabse bada reason yeh hota hai ki hum complex AI words bolte hain, par basic concepts nahi pata hote. Let's clear the absolute basics first!

1. What is an LLM (Large Language Model)?
  • It's a Next-Word Predictor: LLM sochta nahi hai, wo bas probability calculate karta hai ki is sequence ke baad agla shabd (token) kya hona chahiye.
  • Context Window: LLM ki short-term memory. Agar aap uski limit (e.g., 128k tokens) se badi file de doge, toh wo purani baatein bhool jayega. (Isi liye hum chunks me parse karte hain!)
  • Temperature: A number from 0 to 1. 0 = Boring, robotic, predictable (Best for JSON generation). 1 = Creative, wild, unpredictable. Humne apne agents me temperature = 0.3 set kiya hai so we get strict JSON outputs.
2. What is FastAPI?
  • FastAPI vs Flask/Django: Flask synchronous hai (slow). FastAPI **ASGI** (Asynchronous Server Gateway Interface) par based hai. Ye requests ko block kiye bina hazaron users ko ek saath handle kar sakta hai.
  • Pydantic Magic: FastAPI internally Pydantic use karta hai. Agar ek user age ki jagah string "hello" bhejta hai, toh FastAPI request LLM tak jaane se pehle hi 422 Error (Unprocessable Entity) phenk deta hai. Built-in security!
🍔 Synchronous vs Asynchronous (The Restaurant Analogy)

Synchronous (Flask/Django): Tum ek restaurant gaye. Waiter ne tumhara order liya aur tab tak tumhari table par khada raha jab tak chef ne pizza bana nahi diya. Koi doosra customer order nahi de sakta. (Blocking! Very Bad!)

Asynchronous (FastAPI + asyncio): Waiter ne tumhara order liya, chef ko pass kiya, aur turant doosre table par gaya doosra order lene. Jab pizza ready hoga, chef ghanti bajayega aur waiter laakar de dega. (Non-blocking! Super Fast!)

Is project me humne asyncio.gather use kiya hai jisse Activity, Assessment, aur Gap Analyzer ek saath run hote hain (jaise 3 chefs ek saath alag-alag dish bana rahe hon). Isse processing time 50% kam ho jata hai!

3. What is Pydantic v2?

AI bots (LLMs) output hamesha perfect JSON nahi dete. Kabhi string ki jagah number de denge, kabhi field hi gayab kar denge. Pydantic Python ka sabse strict bouncer hai.

  • Agar aap bolo age: int aur AI ne bheja "25" (string), toh Pydantic usko automatically integer me convert kar dega (Type Coercion).
  • Agar conversion fail hua, toh yeh crash hone se pehle bata dega ki kya galat hai. Humare Teacher AI me har agent ka output Pydantic model se valid hokar hi aage badhta hai.
4. WebSockets vs Server-Sent Events (SSE)

Jab hum 10 stages run karte hain, humein user ko dikhana hota hai ki "Stage 2 done, Stage 3 in progress..."

  • WebSockets: Bi-directional (Server aur Client dono baat kar sakte hain). Heavy hota hai, aur corporate firewalls ise block kar dete hain.
  • SSE (Server-Sent Events): Unidirectional. User ek baar request karta hai, aur server us connection par continuously progress updates (events) bhejta rehta hai. Ye lightweight hai aur standard HTTP par chalta hai. Humne yehi use kiya hai!

2. Defensive JSON Parser (llm_utils.py)

LLMs hamesha achhe se behave nahi karte. Kabhi kabhi wo JSON ke upar ```json likh dete hain, jisse standard json.loads() crash ho jata hai. Humne ek regex defense banaya hai.

def extract_json(text):
    # Pehle markdown tags hatao
    text = text.strip()
    if text.startswith("```json"):
        text = text[7:]
    if text.endswith("```"):
        text = text[:-3]
    text = text.strip()
    
    try:
        return json.loads(text)
    except json.JSONDecodeError:
        pass
        
    # Agar abhi bhi corrupt hai, toh pehle { se aakhiri } tak regex se extract kar lo!
    try:
        match = re.search(r'\{[\s\S]*\}', text)
        if match:
            return json.loads(match.group())
    except Exception:
        return None

Chapter 4

Ultimate 30+ Interview Q&A Bank (Pointers Format)

You MUST memorize the logic behind these answers. These are the exact questions they will ask to test your systems engineering depth.

Level 1: Concepts & Foundational Theory
Q1: Single Monolithic Prompt ki jagah 10-Stage Multi-Agent System kyun chuna? Aapne ek hi prompt me saara answer kyun nahi maanga LLM se?
  • Context Window Limits: Ek hi prompt me poora lesson plan, MCQ, aur activities maangne par output limit (e.g. 8k tokens) cross ho jayegi.
  • Formatting Reliability: LLM ek bada JSON likhte hue break ho jata hai aur format corrupt kar deta hai.
  • Agent Specialization: Multi-agent me ek agent sirf planning karta hai, doosra sirf MCQ banata hai. Single responsibility pattern ensures 100% precision.
Q2: WebSockets ki jagah apne Server-Sent Events (SSE) kyun use kiye frontend updates ke liye?
  • Unidirectional Data Stream: Humein sirf server se browser ko progress updates (0% to 100%) bhejni thi. Browser ko wapas server se baat nahi karni thi.
  • HTTP Native: WebSockets alag protocol `ws://` use karte hain aur firewalls me issue dete hain. SSE standard `http://` par chal jata hai.
  • Auto-Reconnect: SSE (sse-starlette) me connection break hone par browser automatically try-reconnect karta hai.
Level 2: Architecture & Implementation (The JD Questions)
Q3: FastAPI kyu use kiya? Flask kyu nahi?
  • Asynchronous ASGI: Flask blocking/synchronous hai. FastAPI async hai, jab LLM API respond kar rahi hoti hai (isme 5-10 sec lagte hain), FastAPI doosre users ki requests handle kar sakta hai.
  • Pydantic Validation Built-in: FastAPI automatic payload validation kar deta hai schemas ke basis par, saving hundreds of lines of boilerplate code.
  • Auto-Documentation: FastAPI automatically Swagger/OpenAPI docs generate karta hai, jo backend engineers ke liye standard practice hai.
Q4: Rate Limiting (HTTP 429) aur API Failover ko system me kaise design kiya hai?
  • 3-Tier Multi-Provider Fallback: Code primary LLM (Groq) ko call karta hai, agar fail hota hai toh sequentially Gemini, aur phir Nvidia NIM par shift hota hai.
  • Exponential Backoff Algorithm: Agar limit exceed error (429) aati hai, hum time.sleep(attempt * delay) lagate hain. (Attempt 1: wait 1s, Attempt 2: wait 2s) taaki token bucket refill ho sake.
  • Zero Downtime Guarantee: User ko backend errors nahi dikhte, API silently switch ho jati hai.
Q5: Python me asyncio.gather aur asyncio.to_thread ka kya role raha is project me?
  • Parallel I/O (gather): Stage 6 (Activities), Stage 7 (Assessments), aur Stage 8 (Gap Analyzer) ko sequential chalane me 40 seconds lagte. Humne inhe asyncio.gather se concurrently run kiya, bringing it down to ~15 seconds.
  • CPU Bound Unblocking (to_thread): PDF parsing ek heavy mathematical/CPU process hai. Isse asyncio event loop freeze na ho, isliye hum is process ko asyncio.to_thread me bhej dete hain (Thread Pool execution).
Level 3: Edge Cases, RAG, & Advanced Scenarios
Q6: RAG-style Source Grounding & Anti-Hallucination Audit kya hota hai? Aur aapne kaise banaya?
  • The Problem: LLMs hallucinate (kuch bhi random knowledge apni taraf se jod dete hain jo PDF me tha hi nahi).
  • The Solution: Stage 9 (Validator) ek Faithfulness Score nikalta hai. Wo generated definitions/keywords ko utha kar original PDF ke raw text me search karta hai (Substring matching / Fuzzy matching).
  • Quality Gate: Agar match 80% se kam aata hai, toh report warning flag raise karti hai ki output halllucinated ho sakta hai.
Q7: Pydantic v2 Schema validation errors ko production me kaise prevent kiya? LLM toh string bhej deta hai integer ki jagah?
  • Defensive Type Coercion: Humne model initilization se pehle explicit string casting lagayi. duration=int(data.get("time", 40)).
  • Default Values: Agar output se poora field hi gayab ho jaye, toh dict.get("key", "default_fallback") se app ko crash hone se bachaya gaya hai.
Q8: Windows OS par [WinError 32] The process cannot access the file because it is being used... error kyu aata hai and fix kya hai?
  • Root Cause: PyMuPDF file ko read karta hai, par OS ko bataata nahi ki "Mera padhna ho gaya hai, ab is file ka handle free kardo". Jab file delete ya move ki jati hai toh Windows mana kar deta hai.
  • Fix: with fitz.open(file_path) as doc:. Python ka Context Manager ensure karta hai ki block ke bahar aate hi memory aur file descriptors automatically explicitly release ho jayein (garbage collection wait kiye bina).
Q9: Agar JD me maanga gaya "Text to Speech (TTS) Integration" add karna ho, toh is system me kahan aur kaise add hoga?
  • Audio Publisher Node: Stage 10 ke baad ek aur asynchronous worker add hoga.
  • Chunking & TTS API: Pydantic output ke "Teacher Script" strings ko extract karke ElevenLabs API ya gTTS (Google TTS) par bheja jayega.
  • Streaming: Backend generate hui MP3 bytes ko StreamingResponse ke through frontend ko bhej dega (chunk-by-chunk).
